## 低風險發現與修正複核

修正前 `ai-endgame-search-check.ts` 只在每次 command 前以觀測更新 `seen`。若最後一筆 Move 才揭露敵兵，loop 結束後輸出仍可能為 `seen=false`。本 reviewer 從實際受審 source 抽出迴圈，僅將command上限縮為1，使用合法單步揭露fixture，直接重現：`commands=1 / seen=false / finalObservationHasEnemy=true / winner=null`。這只影響否定式觀測統計，不會把 `winner=null` 變成 PASS。

root 已在loop結束後新增 `seen ||= observe(state, 0).units.some(u => u.owner === 1);`。使用同一反例複核後得到 `commands=1 / seen=true / finalObservationHasEnemy=true / winner=null`。修正前、修正後腳本與原始log分別保留，沒有覆寫紅燈證據。這個窄驗不讀目標真相給 AI，policy 仍只取得 observe 回傳值。

root 另提供修正後完整1000commands仍 `seen=false / winner=null / exit1` 的結果；本 reviewer 沒有重跑，將其明確列為 root 的執行證據。

## 資料與退出語意

`ai-endgame-search-check.ts` 使用自行建立的合成fixture，沒有讀取生成局save或私有trace。actor0只呼叫 `chooseAction(view)`，其中view來自 `observe(state, state.active)`；actor1是固定合法 EndTurn 的測試oracle。state只供測試建立、applyCommand與終局／觀測統計，不作policy參數。scope明寫不是seed010交戰僵局的原因證明。

該腳本只有 `seen && state.winner === 0` 才輸出 TESTED_PASS；其餘輸出 TESTED_FAIL 並設exit1，timeout/非法command也會斷言失敗。不能把反例順利重現誤算遊戲PASS。相對地，trace腳本exit0表示bounded診斷與逐筆decision parity成功；summary明寫「not a completion or playability gate」，winner仍需獨立判讀。

`ai-decision-trace.mjs` 的正式與instrumented policy皆只收同actor Observation。每筆deepEqual檢查輸入未變，再與正式chooseAction輸出深比對；source seam失配即失敗，不是一個替代遊戲reducer。完整觀測／候選／評分可能結合雙方資訊，所以維持私有是必要限制。
