# 17｜First Playable／首個可玩驗收規格 G1

**狀態**：`PROPOSED`，不是已完成原型。目標先證明「值得玩」，再建立大型 MVP。詳見 ADR-0004。

## 界線
- 一個完整回合制單機對局：24×24 四鄰接方格；1 人類 + 1 AI；兩個可辨識但規則大致對稱的國家；每邊 1 首都、1 步兵、1 斥候。
- 中立村莊約 3–5 座、森林／丘陵／山地／水域／平原；隨 seed 生成；有 1 個可探索異常地點；不要求神秘世界全部現身。
- 金幣為唯一**付費資源**，城市每完整輪 +2（暫定）。3 類單位：步兵、斥候、弓兵。3 個科技：農耕（收入 +1）、弓術（可招弓兵）、探路（斥候視野 +1）。科技以金幣購買；後續科技資源再另建 ADR。
- 每單位有移動和一次攻擊的簡單限制；傷害可預覽、確定性，沒有隱藏隨機暴擊；首都占領為勝利判定；玩家首都陷落為失敗判定（若尚有復國單位，規則需另定；首版不實作復國）。
- Fog：`UNEXPLORED / EXPLORED / VISIBLE`，已見但離開視野不顯示即時敵軍位置。
- 至少一個「異常揭露」事件：4 金幣或地理資訊二選一；事件效果測試由玩家理解且可能改變出兵決策。
- UI：一張地圖 + 情境面板 + 結束回合；至少可鍵鼠操作，手機交互布局可用模擬器先驗收，後續真機測試才算平台完成。
- 儲存：存檔→重新載入→繼續遊戲；同 seed/同 commands→相同 state hash；`SaveVersion`與 `ContentVersion` 明確。

### 技術切片說明
Step 1：headless core 可跑 seed→玩家/AI 命令→勝負（先 CLI/測試）。Step 2：輕量地圖視覺和輸入，能實際完成完整對局。Step 3：異常揭露與 UI；Step 4：人類試玩修改。**不允許 Step 1 直接算 G1 完成**。

## 指令契約
`MoveUnit`, `AttackUnit`, `CaptureSite`, `RecruitUnit`, `PurchaseTech`, `ResolveDiscovery`, `EndTurn`, `SaveGame`, `ContinueAfterVictory`。`SaveGame` 原則上為應用層命令、而非規則事件；應標明哪個 API 不會改動 canonical state。指令至少有 `{requestId, actorId, expectedStateVersion, payload}`。失敗操作不改 state，不消耗金幣，不改 RNG 狀態。

## G1 Done：雙軸驗收
**工程軸（BLOCKING）**：完全可玩人類 vs AI；AI 不作弊且有完成對局的能力；輸入與 UI 一致；指令非法不改狀態；相同 seed/commands 可重播；Fog 對 UI/AI 不洩漏；能存檔重開；授權來源可追溯；至少做一次新增內容/視覺替換演練。

**遊玩軸（BLOCKING）**：使用者本人至少玩完 1 局；提供有趣與乏味的具體場景；判斷是否願意再玩同一規則的不同 seed。若不願意重玩，G1 是 **PLAYABILITY-FAIL**，不能只因測試全部綠燈而升 G2。

## 失敗與止損
- 出生地被卡死、首都不可達、中立村莊無法占領、AI 不動或無限迴圈 → P0。
- 異常事件無法影響任何策略、開局 UI 傳達完整後期世界設定，或平均每回合疲勞程度太高 → 玩法改版，不優先新增技術。
- 不把 96×96/128×128 和 800 單位 benchmark 放進 G1 gate；另建 deterministic synthetic fixture，不拖慢原型。

## 明確不做
外交聯盟完整系統、政治制度、宗教人口、複數資源、魔法戰鬥、航太、海軍、不同世界碰撞引擎、外部 LLM、連線對戰、高級粒子、商店上架。它們都必須保留未來升級接口，不得以假 UI 佔用 G1 開發時間。
